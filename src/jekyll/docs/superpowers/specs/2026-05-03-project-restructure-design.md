# Project Restructure Design

**Date:** 2026-05-03
**Status:** Approved
**Author:** Claude Sonnet

## Overview

Restructure `bitprepared.it` project for cleaner separation between source code, build artifacts, and generated content. Current structure mixes Jekyll source files, build configurations, and generated outputs at root level.

## Goals

1. **Clear separation**: Source code in `src/`, generated content in `output/`
2. **Better Docker management**: Explicit mounts, persistent volumes for caches
3. **Maintainability**: Easier to understand what can be deleted (`output/`)
4. **Permission safety**: All Docker commands use `--user $(id -u):$(id -g)`

## Current Structure Problems

- Jekyll files (`_posts`, `_layouts`, `blog`, `assets`) scattered at root
- Generated `_site/` mixed with source
- `screenshots/` (generated) at root level
- Build configs (`Gemfile`, `package.json`) mixed with content
- Unclear what's safe to delete

## Proposed Structure

```
bitprepared.it/
├── Makefile, CHANGELOG.txt, README.md, LICENSE.txt
├── .gitignore, CLAUDE.md
├── .github/, .git/, .worktrees/
├── src/                          # All source code and build configs
│   ├── jekyll/                   # Jekyll site
│   │   ├── _config.yml, Gemfile
│   │   ├── .htmltest.yml
│   │   ├── _posts, _layouts, _includes, _plugins, _pages
│   │   ├── blog, tags, _eventi, _software
│   │   ├── assets/, docs/
│   │   └── index.html, about.md, robots.txt
│   ├── tailwind/                 # Tailwind CSS config
│   │   ├── package.json, tailwind.config.js
│   └── docker/                   # Docker build files
├── output/                       # Generated content (bind mount)
│   ├── _site/                    # Jekyll output
│   └── screenshots/              # Visual regression screenshots
├── tests/                        # Test baselines (unchanged)
└── scripts/                      # Utility scripts (unchanged)
```

## Docker Configuration

### Volumes (persistent caches)
- `bitprepared-node-modules` → `/workspace/node_modules`
- `bitprepared-vendor` → `/workspace/vendor`
- `bitprepared-jekyll-cache` → `/workspace/.jekyll-cache`

### Bind mounts
- `./src` → `/workspace` (read/write)
- `./output` → `/workspace/output` (write only, generated content)

### Permissions
All Docker commands must use: `--user $(id -u):$(id -g)`

## Jekyll Configuration

**File:** `src/jekyll/_config.yml`

Add:
```yaml
destination: ../../output/_site
cache: ../../output/.jekyll-cache
```

This tells Jekyll to write output outside the source tree.

## Makefile Changes

### Workdir Changes
All Docker commands must use appropriate workdir:
- Jekyll commands: `-w $(PWD)/src/jekyll`
- Tailwind commands: `-w $(PWD)/src/tailwind`

### Command Updates

**`serve`**: Workdir `src/jekyll`, mount `src` + `output`, run `bundle exec jekyll serve`

**`build`**: Workdir `src/jekyll`, generate to `output/_site`

**`build-css`**: Workdir `src/tailwind`, run `npm run build:css`, output to `../jekyll/assets/css/`

**`install-gems`**: Workdir `src/jekyll`, use bundle volume

**`install`**:
- `npm install` in `src/tailwind` (node-modules volume)
- `bundle install` in `src/jekyll` (vendor volume)

**`clean`**: Remove `output/_site`

**`visual-baseline`**: Screenshots → `output/screenshots/`

## Script Updates

### JavaScript Scripts
**`scripts/visual-regression/capture.js`**: Update screenshot paths `screenshots/` → `output/screenshots/`

**`scripts/visual-regression/compare.js`**: Update screenshot paths

**`scripts/optimize-images.js`**: Update `_site/assets/images` → `output/_site/assets/images` (line 32)

**`scripts/analyze-axe.js`**: Update `_site/` → `output/_site/`

### Documentation
**`CLAUDE.md`**: Update all path references to match new structure

## Migration Plan

0. Create new git branch (not worktree)
1. Create new directory structure
2. Move files to correct locations
3. Update `_config.yml` (destination, cache)
4. Update `package.json` (build-css script path)
5. Update Makefile (all Docker commands)
6. Update JavaScript scripts (screenshot/output paths)
7. Update CLAUDE.md (path references)
8. Test: `make build`, `make serve`, `make build-css`
